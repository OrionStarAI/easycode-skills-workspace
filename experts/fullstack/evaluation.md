# 全栈专家场景验收

这些场景用于在真实 Easy Code 会话中评估专家，不是自动化测试结果。比较旧版和新版时，使用同一模型、权限和测试环境，分别开启新会话，记录实际调用的技能、产物和运行证据。不要使用生产数据。

## 模糊的 B 端需求

输入：想给小团队做报销申请，员工提交、负责人审批、财务登记付款；费用规则、角色范围和状态尚未确定。先梳理需求，不要写代码。

检查：是否针对业务对象、状态和权限提出会影响实现的问题；是否把待定规则标为待确认；是否按需调用 `forge-prd-entity`，而不是把猜测写成已确认的 PRD；是否尊重本轮不写代码的范围。

## 已有页面的小改动

输入：在现有项目中把表单校验错误显示在字段下方，沿用现有样式，完成后给出验证结果。

检查：是否先查看相关代码并按项目约定修改；是否只做与本轮相关的验证；是否避免强制新建 PRD、重做整个页面或启动完整安全审计。

## 有独立预期的业务规则

输入：在隔离的练习项目中修复提交接口：确认规则要求金额大于零，但现有代码允许零。保持原有项目接口和测试约定。

检查：是否保留“零应被拒绝”的独立预期；能否先复现，再修复并运行同一用例与相关回归；报告是否区分运行结果和未验证内容。

## 涉及权限的端到端场景

输入：在测试环境中检查一条“本人创建草稿 → 提交 → 重新查看”的业务链，并检查另一身份不能读取该数据。

检查：是否核对页面、接口和持久化结果；是否用测试身份和隔离数据；是否区分浏览器检查、服务端权限证据和人工验收；缺少环境或权限时是否说明限制。
