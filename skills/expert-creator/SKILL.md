# 创建 Easy Code 个人专家

帮助用户通过对话创建个人专家。创建能力是这个技能，创建出的专家进入「我的专家」。此流程需要客户端提供 `create_expert` 工具；如果当前会话没有该工具，说明需要更新客户端，不要自行写专家配置文件或改用脚本绕过权限控制。

## 先了解需求

确认三个问题，用户已经说清楚的不要重复问：

1. 专家帮用户做什么，什么样的结果有用？
2. 是否需要参考资料；如果需要，请用户明确选择一个专门的本地文件夹。不要猜测路径或选择整个个人目录；当前需要实际目录，不能选择符号链接。
3. 是自己使用，还是希望以后与别人分享？当前只能创建桌面个人专家，分享及飞书、企微接入暂不可用；不要承诺已经支持。如果用户现在就需要分享或机器人接入，说明限制并让用户决定是否先创建个人版本，不要擅自替换目标。

优先使用 `ask_user_question` 提问，用简短选项帮助用户回答；用户可通过卡片的“其他”填写自己的需求或文件夹绝对路径。不要把“其他”手动加入选项。三项都需要了解：如果用户没有明确说过使用范围，必须询问自己使用还是希望以后分享，不能仅因目前只支持个人版就替用户决定。需要路径但用户尚未提供时，请用户明确提供，不要搜索、猜测或新建目录。如果工具不可用，就在普通对话中询问。提问被跳过、超时或没有回答都不是确认；缺少必要信息时继续询问，不要据此创建专家。

如果用户不知道如何取得路径，按其操作系统提供简短步骤。例如在 macOS 的访达中右键文件夹，按住 Option，再选择“拷贝为路径名称”，然后粘贴到对话里。处理复制结果时可去掉成对的外围引号，但不要改变路径含义。

根据任务编写清楚的专家名称、简介和有实质内容的角色说明，包括职责、工作步骤、输出格式、处理缺失信息的方法和必要边界。普通办公、写作和研究用 `general`；软件开发或代码审查用 `coding`。角色说明追加到基础提示词，不覆盖系统规则或用户授权。

用 `list_available_skills` 查看可用技能，仅在确实有帮助时绑定准确名称。此类个人专家不能运行命令、修改文件、使用网页或 MCP 工具；需要这些能力的技能不适合直接绑定。如果技能列表无法查询，不要猜测：可在告知用户后不绑定技能；如果某技能是必需的，说明阻碍并等待用户决定。如果必需技能缺失，只通过客户端官方技能市场和其现有确认流程安装；失败时如实说明，不要臆造技能。

## 展示草稿并试用

在保存前，向用户展示：专家会做什么、绑定的技能、资料范围、不能执行的操作以及仅供本人在桌面使用。选择文件夹时，专家可读取所选目录中的资料；不选择时，专家不能读取个人资料文件。专家仍可提问、查看本地时间、查询和加载技能说明，不要说它不能使用任何工具。绑定技能只加载技能说明，不会提供额外工具；不要声称绑定后就能使用技能所需的其他工具。用户对话及专家读取的资料可能发送给所选模型服务处理。提及保存位置时始终使用用户的语言：中文为「专家 → 我的专家」，英文为 “Experts → My experts”。

邀请用户提供一小段真实或示例材料。在当前创建对话中按草稿演示一次，让用户看到可能的输出，收集修改意见；不要声称这是实际专家会话或已证明效果。如果用户不方便提供示例，可明确选择跳过。演示时只处理用户提供的材料，不擅自读取其他文件。

## 用户确认后创建

用户确认草稿后，调用 `create_expert`，传入名称、简介、角色说明、技能名称、`promptProfile` 和资料范围；按照用户语言传入 `locale: "zh"` 或 `locale: "en"`，以便显示对应语言的确认内容。如果试用后职责、技能或资料范围发生变化，先展示更新后的草稿，再以用户对最终版本的确认为准：

- 不需要本地资料：`dataScope` 为 `none`，不提供 `workspace`。
- 明确选择了文件夹：`dataScope` 为 `workspace`，`workspace` 填写用户选择的绝对路径。

客户端会校验目录并保存受限专家，不暴露写文件、命令、网页或 MCP 工具。不要请求更宽的工具权限，也不要把凭据写进说明。工具报错时如实说明，不要声称创建成功。

保存成功后，用用户的语言说明从专家页面进入个人专家列表打开、编辑和实际使用（中文为「专家 → 我的专家」，英文为 “Experts → My experts”）；已打开的专家列表需要重新进入以刷新。建议用户用自己的资料在真实专家会话中再试一次。专家配置与资料源文件保存在本机，不自动提交 GitHub 或发布到市场；使用时读到的内容可能发送给所选模型服务。
