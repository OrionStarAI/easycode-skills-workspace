# 对话创建专家

在普通对话中帮用户创建一个可反复使用的个人专家。这个技能负责引导，创建的结果是客户端「专家 → 我的专家」中的普通专家，用户以后可以编辑或使用现有的机器人接入功能。

## 了解需求

先理解专家要做什么、希望得到什么结果；用户已说明的内容不重复问。信息不足时优先用 `ask_user_question` 提出简短问题，也可以正常对话。不要为了走流程一次问很多无关问题，用户想直接创建简单专家时不必强迫配置高级选项。

根据任务起草专家名称、简介和角色说明。角色说明应写清职责、工作步骤、输出方式和遇到信息不足时怎么处理；普通办公、写作、分析等使用 `general` 提示词，编程任务可使用 `coding`。专家说明是追加的角色指导，不会替代系统规则或用户已有权限。

查看可用技能，只在确实有帮助时绑定实际存在的技能名称；简单专家可以不绑定技能。如果必须的技能尚未安装，说明情况并使用客户端现有的技能安装流程，不要猜测已经安装成功。

## 按需配置

- 用户需要参考本地资料时，询问是否指定一个已有文件夹作为专家工作目录；路径由用户提供，不自行猜测。不知道如何取得路径时，按用户系统简要说明，例如 macOS 访达中选中文件夹、按住 Option 右键并选择“拷贝为路径名称”。工作目录只是工作起点，不是文件访问隔离，不能承诺专家只看得到这个文件夹。对涉及个人或敏感资料的场景，说明所选模型服务可能接收对话和读到的内容。
- 用户希望限制工具时，结合任务与当前可用工具讨论具体选择，明确说明限制后可能影响哪些技能。使用准确的工具名；如果绑定技能需要使用技能工具，也要把相应工具纳入选择。没有要求限制时，不传 `allowedTools`，让专家沿用现有的工具和会话权限；不要默认禁止命令、联网或 MCP。
- 只在用户有需要时配置专家记忆或指定模型。未确认的个人信息、密钥和凭据不要写进专家说明。
- 用户希望分享专家或接入飞书、企微时，说明现有客户端是否支持，并以实际页面和配置为准；不要承诺未实现的分享、文件隔离或自动接入功能。不要因为用户可能以后分享，就擅自改变他当前要创建的专家。

## 确认并保存

在保存前简要展示草稿：专家的职责、绑定技能，以及用户选择的工具、工作目录或其他设置。可根据需要用一小段示例演示或调整，但不要把当前对话中的模拟演示称为真实专家会话测试。让用户确认草稿；跳过、超时或没有回答都不是确认。

用户确认后调用 `create_expert`，传入已确认的 `name`、`description`、`instructions`、`skills` 和 `promptProfile`。只在用户选择时传 `allowedTools`、`workspace`、`model` 或 `memoryEnabled`；按用户语言传 `locale: "zh"` 或 `locale: "en"`。创建工具会再次展示保存确认，不能绕过它。工具不可用或保存失败时如实说明，不自行修改内部配置文件来绕过。

保存成功后告诉用户到「专家 → 我的专家」（英文 “Experts → My experts”）使用或编辑。专家保存在本机；工作目录并不等于知识库的隔离边界，绑定技能也不会自动安装未安装的技能。
