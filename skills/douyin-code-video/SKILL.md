# 代码短视频与抖音发布

帮用户把想法做成可编辑的代码视频，并在用户要求时发布到自己的抖音账号。复用已有技能，不重新实现渲染器或上传工具。用户只要视频时交付视频；只要发布已有视频时使用现有发布技能，不强制重做。

## 准备所需技能

先用 `list_available_skills` 查看可用技能；缺少本轮需要的技能时，用 `search_skill_marketplace` 按下面的精确名称查找，再通过 `install_skill` 的正常安装流程准备。已安装但禁用时使用客户端正常的启用流程；不能安装或启用时说明原因，不把缺失的能力当作已就绪。制作时先用 `use_skill` 加载制作技能；完成成片后如需发布，再加载发布技能。使用技能返回的实际路径和说明。

- **remotion-best-practices**：一般短视频的 React/Remotion 代码、动画和渲染。
- **douyin-publish**：用户要求上传或发布时使用，要求版本 **1.1.0 或更高**。旧版本不会因安装本技能自动升级；使用市场正常更新流程，有本地修改时先核对，不擅自覆盖。无法更新就停止发布并说明。此技能依赖 ego lite 和抖音创作者账号登录态。
- **video-shotcraft** 或 **guizang-product-video-skill**：只有用户明确需要对应的产品宣传视频时按需使用；它们有各自的范围、工作流和依赖，不能把横版模板直接拉伸成竖版。

先处理用户明确指定的内容、受众、风格、时长、素材和发布账号；已给出的信息不要重复问。缺少影响本轮制作的关键信息时再询问。开始前确认用户是只要视频，还是也要求发布；明确说“制作并发抖音”已包含发布意图，不要把已经确认的事反复追问。

## 制作与验证

1. 根据材料提炼主旨，形成简洁的镜头顺序和字幕；重要事实与来源可核实，不捏造用户经历、产品能力或统计数据。复用用户提供且可用的素材，不把私人文件无关内容放进视频。
2. 用户没有指定画幅时，优先设计竖屏 9:16，常用画布为 1080×1920；按用户要求或实际任务调整。为标题、字幕和重要画面留出平台界面遮挡空间。先搭建可复现的视频工程，用 Remotion 代码完成画面和时间轴，不把只生成一段代码当成已出片。
3. 旁白、音乐和封面按用户需求与可用能力准备。没有配音或素材服务时如实说明，不能把静音视频说成有旁白；如需用户决策或服务凭据，通过安全配置流程处理，不让用户把密钥或短信验证码发到聊天中。
4. 按制作技能提供的实际命令渲染可播放的 MP4；检查文件存在且非空，用可用的 `ffprobe` 核验时长、分辨率、视频编码及所需音轨，并检查关键画面和字幕。需要旁白或音乐时还要实际试听或检查可听内容：存在音轨不等于存在有效声音。检查失败先修复或说明，不进入发布。交付可复现工程路径、成片路径和实际检查结果。

## 发布到抖音

仅在用户要求发布时继续。加载 `douyin-publish`，按其说明检查环境和登录状态；确认当前登录账号与用户要求一致。登录失效时在本人设备完成扫码或平台验证，不索取 Cookie、密码或验证码。生成与内容一致的标题、简介及话题，使用用户给定的信息；标题遵守发布技能当前的长度限制。按该技能现有工作流完成必要的信息确认，用户已提供完整信息时不重复确认。

使用刚验证的成片的绝对路径调用发布技能；不要把 `--dry-run` 当作纯本地检查，它会实际把视频上传到创作者表单，但不点击发布。当前发布技能没有自定义封面或定时发布参数；需要这类设置时，引导用户在平台页面操作，并准确报告哪些设置已完成。

发布技能返回 `PUBLISH_SUCCESS` 时才把该次自动操作报告为成功。`PUBLISH_UNCONFIRMED` 或点击后连接中断表示结果未知：先检查作品管理，不能自动再次点击或重传；若之后按账号、标题和时间找到对应作品，依据页面实际显示的发布或审核状态报告。上传失败、登录失效、检测超时、字段不匹配等问题要说明实际状态和可恢复的本地文件；不要称为已发布。
